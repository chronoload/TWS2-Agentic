# 通用质量标准

> 适用于所有 Rmd 写作项目。具体阈值由 config.json 的 content.quality 节控制。

## 一、叙事质量

### 1.1 问题驱动
- 每篇文档从具体的现实问题开始，不是抽象数学/技术问题
- 所有理论引入都服务于解决这个问题
- 概念不是孤立介绍的，而是在解决问题的过程中自然引出

### 1.2 叙事密度
- 每段服务中心问题——能删而不破叙事 → 那是填充，删掉
- 节间因果关系清晰——每节都有"为什么需要下一步"的逻辑连接
- 不存在可删除而不破坏叙事的段落

### 1.3 去 AI 味

| 禁止模式 | 替代方案 |
|---------|---------|
| 教程式开头（"本节将学习..."） | 直接进入问题场景 |
| 百科式介绍（"X 由 Y 于 Z 年创建..."） | 完全不写这些 |
| 空心定义（"X 是基础库"） | 定义+解释+例子，回答"为什么需要" |
| 模板过渡（"接下来进入 K 节"） | 用内容自然过渡 |
| 假对话（"亲爱的读者..."） | 直接陈述 |

### 1.4 风格细则
- 叙事对话感（"请停下来想一想"、"关键的问题在于"）
- 物理先行——每个公式出现之前先给直觉再给数学形式
- 粗体强调关键概念
- 具体数值——先符号求解再代入数据
- Remark 穿插——每 2-3 段一个旁注（历史、类比、注记）
- 善用列表、bulletpoint 和定理环境，一段话不能太长

## 二、结构质量

### 2.1 RE:KCTSW 完整性
- 七节完整，顺序正确
- 标题格式 `# X：{描述性标题}`（H1）
- 开头用 `## 中心问题：{描述}`（H2）

### 2.2 K 节规范
- 每个定义用 `::: definition` 块 + 展开说明
- 包含物理/几何意义 + 具体例子
- 禁止纯表格无叙述

### 2.3 T 节规范
- 至少一个完整的定理→证明→反例闭环
- 证明完整步骤，不跳步，不用"类似地"
- 配反例说明条件为何必要

### 2.4 W 节规范
- 可重复工作流 DAG（步骤链 + 因果箭头）
- 元认知 remark（重新框架化思维方式）
- 桥接下一部分
- 回答 R 的每个子问题

### 2.5 S 节规范
- 代码仅出现在 S 节（setup chunk 除外）
- 代码可运行（正确 import、正确 API）
- 展示数值结果并解释物理含义

## 三、篇幅标准

| 维度 | 默认阈值 | config 字段 |
|------|---------|------------|
| 非代码字符 | ≥20,000 | content.quality.min_chars |
| 总行数 | ≥500 | content.quality.min_lines |
| 每节实质内容 | 不能是一句话或一个表格 | — |
| Filler 比例 | ≤5% | content.quality.max_filler_ratio |

## 四、可视化规则

每个非 S 节配概念性可视化（`{r}` 代码块或 ASCII 图），不是装饰，是概念理解的组成部分。

| 节 | 可视化类型 |
|----|----------|
| R | 问题场景图/实验装置 |
| E | 概念地图/对比矩阵 |
| K | 定义可视化演示 |
| C | 抽象概念视觉类比 |
| T | 定理几何意义/反例图 |
| W | 工作流 DAG 流程图 |
