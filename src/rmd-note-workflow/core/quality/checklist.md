# 通用检查清单

> 每篇文档写完后自查。

## 结构检查
- [ ] 开头用 `## 中心问题：{描述}`（H2）引出具体问题
- [ ] 七节完整（R/E/K/C/T/S/W），用 `# X：{标题}`（H1）格式
- [ ] 所有概念为解决中心问题而引入
- [ ] 代码只出现在 S 节（非 setup 块）

## K 节检查
- [ ] 每个定义用 `::: definition` 块
- [ ] 定义后有展开说明（物理意义/几何直观）
- [ ] 每个定义配具体例子
- [ ] 无纯表格无叙述的定义

## T 节检查
- [ ] 至少一个完整的定义→定理→证明→反例闭环
- [ ] 证明步骤完整，不跳步
- [ ] 反例说明条件为何必要

## S 节检查
- [ ] 有具体数值计算（不是纯符号）
- [ ] 代码可运行（正确 import、正确 API）
- [ ] 展示并解释数值/图形输出

## W 节检查
- [ ] 包含可重复工作流 DAG
- [ ] 元认知 remark（重新框架化思维方式）
- [ ] 桥接下一部分
- [ ] 逐条回答 R 的每个子问题

## 篇幅检查
- [ ] 非代码字符 ≥ {min_chars}
- [ ] 总行数 ≥ {min_lines}

## 质量检查
- [ ] 无 AI 味写法（教程开头/百科介绍/空心定义/模板过渡）
- [ ] Remark 块用于恰当旁注（不滥用）
- [ ] 每 2-3 段有概念性可视化（非 S 节）
- [ ] 叙事对话感，不是字典/百科
